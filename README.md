# Image Playout LAN

**アプリとして使う方は [ダウンロードページ（デスクトップ試用版）](https://github.com/atstti/ImagePlayout/releases/tag/v1.1.6) へ。Node.jsのインストールは不要です。** MacはDMG、WindowsはEXEを選んでください。以下の起動手順はソースコードから実行する方向けです。

操作PCの静止画像をLAN内の別PCへ送出するNode.jsアプリケーションです。操作画面は日本語のダークテーマ、受信画面は画像のみを表示します。既存コードのない新規プロジェクトとして実装しました。

## 必要な環境

- Node.js **22以降**とnpm（Node.js 24 LTS推奨）
- 操作PC：macOS / Windows 10・11
- 受信PC：Chrome / Edge / Safariの現行版
- 同じLANへの接続と、操作PCのTCP 8080番ポートへのアクセス許可

初回の依存関係インストールにはインターネット接続が必要です。インストール後の送出に外部サービスは使いません。

## 起動

```sh
git clone https://github.com/atstti/ImagePlayout.git
cd ImagePlayout
npm ci
npm start
```

macOSでは `start-mac.command` をダブルクリックして起動できます。実行権限がない場合は `chmod +x start-mac.command` を実行してください。Windowsでは `start-windows.bat` を実行します。起動スクリプトは `npm ci` 後にサーバーを起動します。

1. 操作PCで `http://localhost:8080/` を開きます。
2. ユーザー名 **admin**、初回起動で生成された `data/admin-password.txt` 内のパスワードで認証します。パスワードは画面・ログには出力しません。
3. 受信PCで `http://操作PCのLAN内IPアドレス:8080/receiver` を開きます。例：`http://192.168.1.20:8080/receiver`。
4. 受信画面をダブルクリック、または **F** キーで全画面表示します。ブラウザによってはブラウザ自身の全画面機能を使ってください。
5. 停止は起動したターミナルで **Ctrl+C**。

LAN内IPはWindowsの `ipconfig`、macOSのシステム設定「ネットワーク」で確認できます。繋がらない場合はOSのファイアウォールでNode.jsまたはTCP 8080を許可し、Wi-Fiの端末間通信禁止設定を確認してください。

## 操作

- **画像を登録**、またはファイルを画面にドロップ。JPEG / PNG / WebP / GIFを受け付けます。GIFはアニメーションを維持します。
- サムネイルをクリックすると **PREVIEW / NEXT** に設定します。番号・名称・容量・解像度を表示します。
- **CUT**：PREVIEWを瞬時にPROGRAMへ送出。
- **FADE**：PREVIEWを設定時間でクロスフェード。初期値500ms、0〜10000ms。
- **TAKE**：設定欄で選んだCUTまたはFADEで送出。
- **NEXT**：ライブラリの次の画像をPREVIEWへ設定。末尾から先頭に戻ります。
- **AUTO NEXT**：CUT / FADE / TAKE成功後、次の画像をPREVIEWへ設定します。時間指定の自動連続送出ではありません。このチェック状態は操作画面内のみの設定です。
- **BLACK**：準備中の送出を中断し、直ちに黒へ切り替えます。透過背景設定にかかわらず黒になります。
- **↑ / ↓**：送出順を変更。名称変更・削除も可能です。PROGRAM中・送出準備中の画像は削除できません。
- **表示**：FIT＝全体を収める、FILL＝画面を埋める（はみ出しを切る）、STRETCH＝画面に合わせて伸縮。
- **背景**：PNG透過部分やFITの余白の色。設定変更は「設定保存」で確定します。
- キー操作（入力欄などにフォーカスしていないとき）：**Space＝TAKE / →＝NEXT / Esc＝緊急BLACK**。

受信画面はブラウザの表示領域全体に画像を配置します。16:9の出力では1920×1080または3840×2160の画像を推奨します。別比率のモニターでは選択したFIT/FILL/STRETCHが適用されます。ブラウザの全画面許可やOSのスリープ解除は各PCで設定してください。

## 通信と保存

画像本体はHTTP `/media/:id` で配信し、指示と状態はWebSocket `/ws` で同期します。画像の内容を検証し、ファイル名とは無関係なUUIDでサーバーに保存します。日本語ファイル名は表示用メタデータとして保持します。

PREVIEWを事前読み込みし、送出操作時には接続中の**全受信PCの読み込みACK**を待ちます。最大8秒で確認できない、読み込みに失敗する、待機中の端末が切断される場合は送出を中止し、原因を操作画面に表示します。BLACKはACKを待ちません。ACKはブラウザの画像読み込み完了の確認であり、物理ディスプレイへの出力完了の保証ではありません。

命令には永続化したシーケンス番号を付け、古い命令と非同期読み込みの逆転を受信側で拒否します。切断中は最後の画面を保持し、0.5〜10秒の間隔で再接続し、PROGRAMを復元します。サーバー再起動でシーケンスが小さくなった場合も再接続を起点として復元します。

各受信PCの接続状態、最終応答、表示画像ID、シーケンス、読み込みエラーを表示します。切断した接続は直近20件をサーバーメモリ内に残します。同じPCの再接続は別の接続IDになります。

画像、並び順、名称、PREVIEW / PROGRAM、設定、シーケンスは `data/` に保存します。状態ファイルは一時ファイルからの置換で更新します。再起動後はPROGRAMを復元します。バックアップはサーバー停止後に `data/` ごとコピーしてください。ファイルを手動で編集・削除しないでください。状態JSONの破損時は上書きせず起動を停止するため、バックアップから復元してください。複数サーバープロセスで同じデータディレクトリを共用しないでください。

画像はブラウザのHTTPキャッシュに保存し、事前読み込み用の参照は12画像まで保持します。キャッシュ削除の専用UIは未実装です。

## 設定

`config.json`：

| 項目             | 初期値   | 内容                                                         |
| ---------------- | -------- | ------------------------------------------------------------ |
| port             | 8080     | HTTP / WebSocketのポート                                     |
| host             | 0.0.0.0  | 全LANインターフェースで待機                                  |
| maxUploadMB      | 30       | 1ファイルの容量上限                                          |
| maxPixels        | 50000000 | デコード時の総画素数上限（アニメーションの全フレームを含む） |
| fadeMs           | 500      | データがない初回起動時のFADE時間                             |
| preloadTimeoutMs | 8000     | 全受信PCのACK待機上限                                        |

環境変数 `PORT`、`DATA_DIR`、`ADMIN_PASSWORD` でポート、保存先、操作パスワードを上書きできます。`.env` の自動読み込みはしません。例：

```sh
# macOS / Linux
ADMIN_PASSWORD='任意の長いパスワード' npm start
```

```powershell
# Windows PowerShell
$env:ADMIN_PASSWORD='任意の長いパスワード'
npm start
```

Basic認証を使うため、共用PCで操作した後はブラウザを終了してください。HTTP上の認証情報と画像は暗号化されません。信頼できるLANで使い、インターネットへ直接公開しないでください。受信URLと画像URLはLAN内で認証不要です。受信接続から操作命令・アップロードは実行できません。操作APIと管理WebSocketは認証・ブラウザOrigin検査を行います。画像の実形式とデコードを検証し、SVG等の未対応形式、破損画像、上限超過を拒否します。

## 実装範囲と今後の課題

Phase 1の画像登録、PREVIEW / PROGRAM、CUT / FADE / TAKE / BLACK、LAN受信、WebSocket同期を実装済みです。Phase 2以降の基盤として、並べ替え、名称変更・削除、NEXT / AUTO NEXT、接続監視、永続化、複数受信ACK、キーボード操作も実装しています。

今後の段階的な実装対象：名前付きプレイリストの保存・読み込み、画像ごとの表示時間・トランジション・次画像指定、時間指定自動送出、受信PC別の設定、専用PNGオーバーレイレイヤー、キャッシュ管理UI、送出ログ、予定時刻による送出です。PNG画像自身の透過には対応しています。

現在はACK後に各端末へ同じ命令を配信します。LANの遅延・ブラウザの描画・GIFの再生開始などに差があるため、**フレーム単位の完全同期は保証しません**。表示できない受信端末がある場合は接続状態を確認してから再送出してください。

## ダブルクリックで使える配布版（v1.1.0）

Electronでサーバーと操作画面をまとめたデスクトップ版を追加しました。配布ファイルを受け取る人はNode.js・npmをインストールする必要がありません。MacはDMGからアプリを配置、WindowsはポータブルEXEを開くと操作画面が起動します。操作画面は自動認証し、LAN内の別ブラウザでの操作には引き続き認証が必要です。

受信URLの確認・コピー、同じPCでのOUT表示、データ保存先の確認はアプリの「送出」メニューから行えます。詳しい利用・移行手順は [配布版の使い方](docs/配布版の使い方.md) を参照してください。

### 開発用の起動とビルド

ソース版とデスクトップ版は同じポートを使います。`npm start` を終了してから実行してください。開発にはNode.js 22.12以降（24推奨）が必要です。

```sh
npm ci
npm run desktop
```

`npm run desktop` は初回にElectron本体をダウンロードします。利用者に渡すファイルにはElectron・Node.js・画像デコーダーを同梱するので、配布版の初回起動にはダウンロード不要です。

```sh
# macOS上で、そのMacと同じCPU向けを作成
npm run dist -- --mac --publish never
# Windows上で、64bit版を作成
npm run dist -- --win --x64 --publish never
```

生成物は `dist/` に保存します。sharpのネイティブ依存関係を同梱するため、対象OS・CPUと同じ環境で `npm ci` とビルドを実行してください。`.github/workflows/desktop.yml` はmain更新時、またはActionsの手動実行で、Apple Silicon Mac・Intel Mac・Windows x64の3環境でビルドします。ビルドした実アプリの自動ログイン、画像登録、CUT、受信URL、データ分離も各環境でスモークテストします。成功した配布ファイルはActionsのArtifactsから取得できます。GitHub Releasesへの公開は、ビルド成功後に「Publish desktop preview」ワークフローを手動実行して行います。入力するrun_idは成功した「Desktop packages」の実行IDです。検証済みの3ファイルとチェックサムを試用版として公開し、既存リリースは上書きしません。

アプリはASARにまとめ、ネイティブ画像デコーダーは展開して同梱します。開発時のdata、テスト、Git履歴、秘密情報は配布対象に含めません。保存先の変更が必要な場合は環境変数 `IMAGE_PLAYOUT_USER_DATA` でアプリ用データディレクトリを指定できます。通常は設定不要です。

Appleの署名・公証、Windowsのコード署名は未設定です。一般向け配布で初回警告を減らすには、配布者の証明書を用いた署名工程の追加が必要です。

## OBSのブラウザソースで透過合成（v1.1.1以降）

通常のOUTは背景色を描画します。OBSで下の映像にPNGを重ねる場合は、次の**透過専用URL**をブラウザソースに設定してください。

```text
http://操作PCのIPアドレス:8080/receiver?transparent=1
```

OBSと操作PCが同じPCなら `http://localhost:8080/receiver?transparent=1` です。
操作画面右上の「透過OUTのURLをコピー」、デスクトップアプリの「送出 → OBS用の透過OUT URL…」からも確認できます。

1. v1.1.2以降へ更新し、操作アプリを起動します。旧版を起動したままにしないでください。
2. OBSの「ソース」で「ブラウザ」を追加します。「ローカルファイル」はオフにします。
3. 上記URLを設定し、幅・高さは出力に合わせます（例：1920×1080）。
4. OBSでこのブラウザソースを、下地となる映像ソースより上へ配置します。
5. アルファを持つPNG等を選んでCUT / TAKEします。PNGの完全透明・半透明部分とFITの余白は下の映像が見える状態になります。

透過モードはURLごとの設定です。背景色の設定は通常OUTに適用され、透過OUTでは使用しません。JPEGなどアルファのない画像は画像自体が不透明です。BLACKおよび初期の画像未送出状態は、透過モードでも不透明な黒です。下の映像だけを表示する場合はCLEAR（透明）を押します（v1.1.2以降）。

通常のブラウザやHDMI出力の見た目だけではアルファを確認できません。OBSの下地映像を含むプレビューで確認してください。通常のHDMI出力にアルファチャンネルを追加する機能ではありません。更新後に古い表示が残る場合はOBSのブラウザソースの「現在のページのキャッシュを更新」を実行してください。

Chromiumの背景なしスクリーンショットをデコードし、PNGの透明・半透明・不透明部分がそれぞれアルファ0 / 128 / 255であることを検証しています。FADE・背景色変更・再読み込みでも保持し、通常OUTおよびBLACKは不透明のままであることも確認しています。OBSアプリ自体での実機テストは未実施です。

## CLEAR：何も重ねず、透明だけを出す（v1.1.2以降）

操作画面の **CLEAR（透明）** を押すと、送出中の画像を外して、透過OUTを完全透明（全画素アルファ0）にします。OBSで下の映像だけを見せたいときに使います。OBSのブラウザソースは引き続き `/receiver?transparent=1` を指定してください。

- **CLEAR（透明）**：何も重ねない。透過OUTでは下の映像がそのまま見えます。
- **BLACK**：不透明な黒を重ねる。Escキーの緊急BLACKも同じです。
- **CUT / FADE / TAKE**：PREVIEWの画像を再び重ねます。CLEARでPREVIEWは変わりません。

CLEARは画像の読み込みACKを待たずに実行し、準備中の送出や実行中のFADEも中断します。CLEAR状態は保存し、再接続・サーバー再起動後も復元します。操作側のPROGRAMは「CLEAR（透明）」と市松模様で区別し、受信PCの表示状態にもCLEARを表示します。市松模様は操作画面の確認用で、OUTには出しません。

背景色付きの通常OUT（`/receiver`）は、CLEAR時も黒く見えます。通常ブラウザの画面やHDMIからアルファを送る機能ではありません。OBSの合成には透過専用URLを使ってください。初回起動時および従来の保存データで画像未送出の場合は、互換性のためBLACKのままです。

## 透過OUTのURLをコピー（v1.1.3以降）

右上の出力操作は **「透過OUTのURLをコピー」ボタン1つ** にまとめました。押すと `/receiver?transparent=1` のURLをクリップボードへコピーし、「コピーしました」と表示します。ブラウザ・タブ・ウィンドウは開きません。そのままOBSのブラウザソースのURL欄へ貼り付けてください。

LAN上のアドレスで操作画面を開いている場合は、その接続先ホストとポートを使います。デスクトップ版・localhostで開いている場合は、サーバーのLAN用IPv4を優先します。複数のネットワークに接続している場合、プライベートIPv4の最初の候補が選ばれます。別の候補が必要なら「送出 → OBS用の透過OUT URL…」から確認してください。LANアドレスがない場合はローカルURLになります。

HTTPSやlocalhostのClipboard APIに加え、LAN内のHTTPではコピーコマンドを使います。ブラウザ側でコピーが拒否された場合は、失敗のメッセージとURLを表示するので、URLを手動でコピーしてください。新しい画面に自動移動することはありません。

## PREVIEW / PROGRAMの透過確認（v1.1.3以降）

操作画面のPREVIEWとPROGRAMは、PNGの透明・半透明部分およびFITの余白を市松模様で確認できます。設定したOUT背景色とは独立した確認表示です。PROGRAMがBLACKのときは不透明な黒、CLEARのときは全面が市松模様になります。市松模様は受信側の画像や透過OUTには描画しません。

## 左側の画像ライブラリ（v1.1.4以降）

画像ライブラリを左側、PREVIEW / PROGRAMと送出操作を右側に配置しました。ライブラリをスクロールして画像を選んでも、右側のモニター位置は動きません。選択・送出・受信状態の更新後もライブラリのスクロール位置を維持します。長いファイル名は2行まで表示し、マウスを重ねると全名を確認できます。

右側も独立してスクロールするので、設定や受信PC一覧を確認できます。画面幅760px以下の小さなブラウザでは上下配置になります。OUTの表示や送出機能には変更ありません。

## 縦並びライブラリと固定した操作位置（v1.1.5以降）

画像ライブラリは横に複数並べず、1画像1行の縦リストにしました。サムネイル上の「No. 01」などの独立したバッジが並び順の番号です。ファイル名の欄にはファイル名だけを表示します。名称変更・削除・並べ替えは各行の下にあります。

モニター下のファイル名・状態名の欄は固定の高さにしました。英数字のファイル名から「CLEAR（透明）」へ切り替わるときの日本語フォントによる2pxの高さ変化を解消し、CLEAR / BLACK / 画像送出やPREVIEW選択で操作ボタンがずれないようにしています。

## カード全体の選択・名称変更・コピー通知（v1.1.6以降）

画像カードはサムネイルだけでなく、枠・余白・ファイル名・サイズ欄をクリックしてPREVIEWへ選択できます。カードにキーボードでフォーカスし、Enterでも選択できます。並べ替え・名称変更・削除ボタンは独立した操作で、押してもその画像を選択しません。

名称変更は、デスクトップ版で非対応のブラウザ `prompt()` からアプリ内ダイアログに変更しました。名称を入力して保存またはEnterで確定、キャンセルまたはEscで閉じます。名称変更中のEscはBLACKを送出しません。空白だけの名称は保存できず、保存に失敗した場合はダイアログ内に原因を表示します。変更は表示名に適用し、画像ID・画像本体・PROGRAMには影響しません。

URLコピー成功時の「コピーしました」は約1秒で消えます。連続して押した場合は最後のコピーから1秒です。通知はレイアウトに影響しない位置に表示するため、表示・消去でボタン位置は変わりません。コピー失敗時のメッセージは確認できるように残します。
